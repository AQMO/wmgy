## 1. 数据库详细设计（MySQL 8 / InnoDB / utf8mb4）

### 1.1 ER 关系总览

```
user 1───0..1 store（商家开一店）
store 1───* category（店铺商品分类）
store 1───* product，product *───1 category
user 1───* cart_item，cart_item *───1 product
user 1───* order（消费者），store 1───* order
order 1───* order_item，order_item *───1 product（含规格快照）
order 1───* order_log（状态/物流变更日志）
store 1───* settlement_flow（资金流水）
1 commission_rule（全局）+ store 可覆盖专属比例
```

### 2.2 认证与权限设计

**登录流程**
1. `POST /api/auth/login` 校验用户名密码（BCrypt.matches）。
2. 签发 JWT（HS256）：payload = `{uid, role, exp=24h}`，密钥从配置读取。
3. 前端存 Pinia + localStorage，Axios 请求拦截器统一附加 `Authorization: Bearer`。

**鉴权链路**
```
请求 → JwtInterceptor（解析Token，注入 userId/role 到 request attr）
     → HandlerMethod 含 @RoleRequired({MERCHANT}) → 角色不匹配 → 403
     → 白名单（/api/auth/**, GET /api/stores/**, GET /api/products/**）直接放行
```

### 2.4 关键业务逻辑

**下单（OrderService.createOrder）**
1. 校验商品上架 + 库存充足；`UPDATE t_product SET stock = stock - ? WHERE id=? AND stock >= ?` 条件更新防超卖。
2. 生成订单号；快照收货信息与商品明细；计算 total/freight/pay_amount。
3. 抽成规则**快照**记录于订单（下单时按当前生效规则模式记录，完成时精确计算）。
4. 清空购物车对应项；写订单日志「创建订单」。

**模拟支付（PayService.mockPay）**：UNPAID→UNSHIPPED，写 paid_at 与日志；店铺冻结金额增加（货款进入冻结期）。

**自助发货（OrderService.ship）**
1. 校验：订单属当前商家 && 状态=UNSHIPPED（仅待发货可见发货入口，PRD 2.3-1）。
2. 必填快递公司+单号；同店重复单号拦截（PRD 2.3-3）。
3. UNSHIPPED→SHIPPED，回填 express 字段与 shipped_at；写订单日志；一次发货不可重复（PRD 2.3-6）。

**修改物流（OrderService.updateExpress）**：仅 SHIPPED（未签收）允许；每次修改写日志留痕（PRD 2.3-4）。

**确认收货（OrderService.confirm）**：SHIPPED→COMPLETED；触发结算：
- 抽成 = 实付基数 × 比例 或 固定金额；基数是否含运费按生效规则。
- 货款 - 抽成 入商家可提现余额；写 ORDER_IN / COMMISSION 两条流水。

**提现（SettlementService.applyWithdraw）**：校验余额充足 → 余额扣减 → 生成 PENDING 提现单 + WITHDRAW 流水。

**入驻审核（AdminService.auditStore）**：PENDING→ACTIVE（开通店铺，缴保证金流水）/CLOSED；冻结 FROZEN 禁止商家端交易操作。

## 4. 安全设计
1. JWT 签名 HS256，密钥配置于 `application.yml`（生产换环境变量）。
2. BCrypt 强度 10 存储密码。
3. 横向越权：商家/买家侧接口一律以 Token 解出的 userId/storeId 过滤，不信任前端传参。
4. 前端展示统一转义（Vue 默认转义插值），富文本详情仅商家自填。
5. 所有写操作留 operation_log。
