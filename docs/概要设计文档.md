## 1. 引言

### 1.1 编写目的
本文档基于 PRD 完成系统总体设计，明确系统架构、功能模块划分、技术选型与数据流转，作为详细设计与编码实现的依据。阅读对象为开发、测试与项目管理人员。

### 1.2 实现范围（一期核心交易闭环 + 认证体系）
- **用户认证**：注册 / 登录 / JWT 鉴权 / 三角色权限（平台管理员、果园商家、消费者）。
- **消费者端**：果园店铺浏览、商品详情、购物车、下单支付（模拟）、订单列表/详情。
- **商家端**：入驻申请、店铺装修、商品分类与商品管理（上下架）、订单处理、**自助发货（快递公司+单号）**、资金流水与提现申请。
- **平台后台**：商家入驻审核、店铺开通/冻结、抽成规则配置（比例/固定金额）、保证金配置、全平台订单监控、数据大盘。
- **资金规则**：平台抽成计算、商家可提现余额、冻结金额、结算流水。

二期功能（电子面单、物流异常预警、采摘预约、营销分摊、溯源、会员积分）在设计中预留扩展点，不在本期编码范围。

### 1.3 术语
| 术语 | 说明 |
|---|---|
| 多商户 | 一个果园 = 一家独立店铺，数据完全隔离 |
| 保证金 | 商家入驻缴纳的履约担保金 |
| 抽成 | 平台按规则从订单实付金额中扣除的佣金 |
| 自助发货 | 商家在待发货订单上录入快递公司与快递单号 |

### 2.3 部署架构
开发环境前后端分离部署：前端 Vite Dev Server（代理 `/api` → 后端 8080），后端内嵌 Tomcat。生产可 Nginx 统一入口，静态资源与 `/api` 反向代理分发。

## 3. 功能模块划分

```
万亩果园平台
├── 01 认证与用户模块        注册/登录/微信登录/角色鉴权/个人信息
├── 02 店铺模块             入驻申请、审核开通、店铺装修、冻结/关停
├── 03 商品模块             分类管理、商品 CRUD、上下架
├── 04 交易模块             购物车、确认订单、模拟支付、订单状态机
├── 05 物流发货模块          自助发货、重复单号校验、签收前可修改
├── 06 资金结算模块          抽成计算、余额/冻结金、提现申请、流水
├── 07 平台管理模块          商家审核、抽成规则、保证金配置、订单监控、数据大盘
├── 08 聊天模块（V1.1 新增）  买家↔商家一对一消息、未读角标、平台聊天监控
├── 09 消息通知模块（V1.1）   订单/审核/结算事件站内通知、未读轮询
└── 10 流量监控模块（V1.1）   店铺/商品访问埋点、商家 PV/UV、平台流量排行
```

### 3.0 端形态（V1.1 补充）
| 端 | 实现 |
|---|---|
| 消费者移动端 | **微信小程序（uni-app Vue3）** + H5 页面双端并存，共用同一套 `/api` |
| 商家端 | PC Web 工作台 |
| 平台后台 | PC Web 管理后台（含聊天监控、流量监控） |

### 3.1 订单状态机

```
待付款 ──支付成功──→ 待发货 ──商家发货──→ 已发货 ──确认收货──→ 已完成
   │                   │
   └─取消──→ 已取消      └─退款──→ 已退款（一期简化：平台记录）
```

### 3.2 资金流转

```
消费者支付 → 订单冻结金额(全额) → [已完成且无售后] → 扣除平台抽成
           → 货款入商家可提现余额 → 商家提现申请 → 平台打款（一期记录）
```

## 4. 关键设计决策

| # | 决策 | 说明 |
|---|---|---|
| D1 | 无状态 JWT 认证 | 三端（小程序/Web/后台）统一 RESTful API，Token 携带 userId+role，服务端拦截器校验 |
| D2 | 单库多商户 + store_id 数据隔离 | 所有商家侧业务表冗余 `store_id`，Service 层强制以当前登录商家店铺过滤查询，实现数据隔离 |
| D3 | 抽成规则版本化 | 抽成规则表带 `effective` 标记，下单时快照规则到订单，规则修改仅对新订单生效（PRD 5.2） |
| D4 | 发货单号唯一性 | 订单表 `(store_id, express_no)` 业务校验拦截同商家重复单号（PRD 2.3-3） |
| D5 | 操作日志留存 | `operation_log` 表记录发货/审核/提现等关键操作，永久留存（PRD 非功能6） |
| D6 | 模拟支付 | 一期不对接真实微信/支付宝，支付接口模拟回调，预留 `PaymentService` 扩展点 |

## 5. 接口总体规范

- 前缀：`/api`
- 统一响应体：`{ code: 0, msg: "success", data: {...} }`，非 0 为业务错误。
- 认证：`Authorization: Bearer <token>`；公开接口白名单：登录、注册、店铺/商品浏览。
- 分页参数：`page`（0 起）、`size`；响应：`{ total, list }`。
- 错误码段：0 成功；4xx01 参数错误；4xx02 未认证；4xx03 无权限；5xx01 业务异常。

## 6. 非功能性设计

1. **数据隔离**：商家端所有查询在 Service 层注入 `store_id` 条件，防越权（横向）。
2. **密码安全**：BCrypt 加盐存储，Token 默认 24h 有效。
3. **参数校验**：Controller 层 `@Validated` + 全局异常处理器统一返回。
4. **SQL 安全**：全部经 Hibernate 预编译绑定，无拼接 SQL。
5. **可扩展性**：二期功能（采摘/溯源/营销）以独立表 + 功能开关表（预留）扩展，抽成配置已按业务类型预留 `bizType` 字段。
